# Проверенный поставщик — чат-бот и мини-приложение в MAX

Трек «Эффективный бизнес». Закупщик малого и среднего бизнеса пишет, что ему нужно, обычными словами и получает
5 поставщиков с объяснением, почему они попали в подборку, какие сведения о них найдены, из какого источника и на какую дату.

- **Бот:** https://max.ru/t711_hakaton_max_bot
- **Мини-приложение:** https://2-26-104-162.sslip.io
- **Репозиторий:** https://github.com/kolomyts192/mini-app-max-supplier

Сервис не выставляет рейтинг надёжности и не гарантирует качество, наличие товара или исполнение договора:
он показывает только факты из официальных источников.

## Назначение решения

Найти поставщика и понять, можно ли ему доверять, обычно значит несколько часов ручной работы: поиск в интернете,
проверка по реестрам, сравнение в таблице. Решение сводит это к диалогу с ботом и короткой подборке в мини-приложении MAX:

- запрос пишется свободным текстом, без кодов ОКВЭД и без регистрации;
- в подборке до 5 компаний, у каждой есть блок «Почему в подборке»;
- у каждого факта указан источник и дата проверки;
- подборку можно сравнить, сохранить и запросить у поставщиков коммерческое предложение (КП).

## Основной пользовательский сценарий

1. Пользователь пишет боту: «Нужна фанера ФСФ 18 мм в Татарстане, только производитель».
2. Бот распознаёт товар, характеристики, регион, тип поставщика, объём и требования к документам. Недостающее
   уточняет, не больше трёх вопросов.
3. После подтверждения бот пишет «Отобрал 5 из N», показывает трёх лучших (у каждого — чем подтверждён тип
   поставщика) и присылает кнопку «Открыть подборку».
4. В мини-приложении открывается выдача с заполненными параметрами: заголовок «5 лучших из N», строка
   «Проверено: реестр МСП · ФНС · ЕГРЮЛ · Росаккредитация», карточки поставщиков.
5. Отбор: из категории товара убираются компании с прекращённой деятельностью. По желанию включаются строгий регион,
   «только производитель», «нужны документы». Оставшиеся оцениваются по формуле:
   `Score = 0.35·Товар + 0.20·Регион + 0.15·ТипПоставщика + 0.10·ЮрПроверка + 0.10·Документы + 0.05·ПолнотаПрофиля + 0.05·Свежесть`.
   При равном балле выше те, у кого товар подтверждён документом, затем выручка, число сотрудников и более
   давняя регистрация.
6. В карточке поставщика: ЕГРЮЛ (статус, руководитель, адрес), реестр МСП, продукция, документы Росаккредитации,
   налоги, риск-сигналы, контакты, источники и ограничения.
7. До трёх поставщиков можно сравнить и сохранить подборку. «Запросить КП» из выдачи, карточки и сравнения
   готовит текст запроса: его можно отправить в чат MAX или скопировать, а сайт и телефон найти по ИНН.
8. Через двое суток после запроса КП бот спрашивает «Поставщики ответили?». При ответе «нет» он присылает
   подборку заново. Ответы сохраняются: это метрика «дошли до контакта».

Команды бота: `/start`, `/find`, `/saved`, `/help`, `/cancel`.

## Состав и архитектура

```
MAX (чат) ──► бот (long polling или webhook) ──┐
                                               ├──► сервис поиска ──► PostgreSQL (компании, документы, подборки)
MAX (мини-приложение) ──► API /api/* ──────────┘          │
                                                          ├──► Redis (сессии бота, search_token, кэш, очередь)
                                                          └──► GigaChat, DaData (необязательно)
```

Один контейнер `app` (Node.js 22, Fastify) обслуживает бота, API мини-приложения и отдаёт собранный фронтенд.

```
server/                  бэкенд: Node.js + TypeScript
  src/bot/               диалог бота: состояния, сессии, тексты, клавиатуры
  src/max/               клиент MAX Bot API, проверка initData, дедупликация событий
  src/parser/            разбор свободного запроса: товар, регион, объём, тип поставщика
  src/ai/                разбор запроса и оценка кандидатов через GigaChat
  src/search/            отбор, ранжирование, объяснение выдачи
  src/sources/           адаптеры источников: повторы, circuit breaker, кэш
  src/opendata/          импорт официальных открытых данных
  src/services/          search_token, подборки, запрос КП, аналитика, аудит
  src/http/              API мини-приложения, webhook, авторизация, rate limiting
  migrations/            схема PostgreSQL
  certs/                 сертификат Минцифры для TLS к platform-api2.max.ru
  test/                  модульные, контрактные и E2E-тесты
webapp/                  мини-приложение: React 18 + TypeScript + Vite
data/catalog.json        справочник: 17 категорий, 77 товаров, регионы, единицы, требования к документам
data/suppliers.json      тестовая база: 63 вымышленные компании
data/search-golden.json  золотой набор из 40 запросов для оценки качества выдачи
deploy/Caddyfile         HTTPS-прокси для сервера
docker-compose.yml       локальный запуск: app, postgres, redis
docker-compose.prod.yml  запуск на сервере: то же и Caddy с HTTPS
```

## Запуск одной командой

Нужен Docker с Compose v2. Node.js локально не требуется.

```bash
cp .env.example .env
docker compose up -d --build
```

Откройте http://localhost:8080. В обычном браузере мини-приложение работает без MAX (`ALLOW_BROWSER_DEMO=true`).

- Первая сборка занимает 2–3 минуты.
- При старте применяются миграции и загружается тестовая база из 63 компаний. Пока официальные данные не
  импортированы, поиск идёт по ней, а выдача помечена «Демо».
- Реальные данные (204 тыс. компаний) загружаются отдельно, см. [Работа с данными](#работа-с-данными).
- Чтобы заработал бот, укажите в `.env` `MAX_BOT_TOKEN` и оставьте `MAX_UPDATES_MODE=polling`.
  Один токен — один запущенный сервер: два сервера с одним токеном перехватывают сообщения друг у друга.

Сервис `platform-api2.max.ru` использует сертификат «Russian Trusted Root CA» Минцифры. Он лежит в
`server/certs/russian_trusted_ca.pem` и подключается через `NODE_EXTRA_CA_CERTS`.

Чтобы мини-приложение открывалось из бота, его адрес указывается на платформе MAX для партнёров:
Чат-боты → бот → Настройки → ссылка на мини-приложение.

В базе после импорта: 204 399 компаний по всей России, все 17 категорий, около 188 тыс. документов.

**Загрузка реальных данных.** Нужны около 10 ГБ свободного места (архивы ФНС — 3,7 ГБ):

```bash
docker compose run --rm app node dist/opendata/cli.js all
docker compose run --rm app node dist/opendata/cli.js verify
```

`all` скачивает наборы ФНС и импортирует их, `verify` проверяет результат (дубли, пустые регионы, категории, наборы).
Импорт занимает около 5 минут после скачивания; скачивание зависит от канала. Росаккредитация загружается командой
`cli.js fsa`: с российского IP она скачивает архивы сама, иначе архивы кладут в том `opendata` вручную и запускают
`cli.js fsa --offline`. Остальные команды: `download`, `analyze` (диагностика без записи в БД), `import`, `enrich`,
`rnp`, `report`. Перед импортом стоит сделать резервную копию: `docker compose run --rm backup`.

**Как данные попадают в продукт.**

- Тип поставщика не определяется по одному ОКВЭД. Производитель — это компания, которая указала производимую
  продукцию в реестре МСП или названа изготовителем в сертификате либо декларации Росаккредитации. Основание
  (с номером документа) показывается в карточке, остальные получают «Тип не определён».
- Статус «Действует» берётся из ЕГРЮЛ, а без него — по факту включения в реестр МСП на дату набора.
- Характеристики запроса («18 мм», «марка ФСФ») сверяются с названиями продукции в документах и подтверждаются цитатой
  с номером документа. Если характеристики в документе нет, выдача так и пишет: «не указано, уточните у поставщика».
- GigaChat помогает понять запрос и оценить кандидатов, но факты берутся только из реестров. Его оценка учитывается,
  только если ссылается на реальную строку сведений кандидата. Простые запросы разбираются правилами без GigaChat.
- Для реестров, которые не подключены, интерфейс пишет «не проверялось», а не «записей не найдено».
- Подборки, история и ответы на «Поставщики ответили?» хранятся в PostgreSQL по MAX ID.
- Логи — структурированный JSON, токены, `initData`, телефоны и email маскируются.

## Тестовые данные

- `data/suppliers.json` — 63 вымышленные компании. ИНН и ОГРН начинаются с несуществующего кода региона «00»,
  в интерфейсе у них бейдж «тестовые данные».
- Загружаются при каждом старте (`SEED_ON_START=true`) и не затрагивают реальные данные.
- Без импорта официальных данных поиск работает по ним и показывает пометку «Демо».
- `SEARCH_DATA=test` — только тестовая база, `SEARCH_DATA=all` — обе. После изменения `docker compose up -d`.
- В тестовой базе есть производители, дистрибьюторы, документы, записи ГИСП и риск-сигналы, на них видна работа всех фильтров.
- Имитация отказа источника: `SIMULATE_SOURCE_FAILURES=FSA_DECL,SME_REGISTRY`. Поиск продолжит работать,
  в выдаче появится предупреждение «Часть сведений сейчас недоступна».
- Пересоздать тестовую базу: `docker compose run --rm tools sh -c "cd server && npm ci && npm run gen:data"`.
- `data/search-golden.json` — 40 запросов по всем 17 категориям для проверки выдачи на реальных данных:
  `cd server && npm run search:eval -- --url http://localhost:8080`.

**В MAX:**

1. Откройте https://max.ru/t711_hakaton_max_bot и отправьте `/start`. Бот покажет источники с датами и кнопки.
2. Нажмите «Пример запроса» или напишите: «Нужна фанера ФСФ 18 мм в Татарстане, только производитель».
3. Бот покажет распознанные параметры. Подтвердите их.
4. Бот ответит «Отобрал 5 из N» и тремя лучшими с основанием типа поставщика.
5. Нажмите «Открыть подборку»: в мини-приложении откроется выдача с заполненными параметрами.
6. Откройте карточку компании: ЕГРЮЛ, документы, источники с датами. Нажмите «Запрос КП», чтобы получить готовый текст.
7. Нажмите «Сравнить» у двух-трёх компаний, затем «Сохранить подборку». Команда `/saved` покажет её в чате.

**Локально, без MAX:**

1. `docker compose up -d --build`, дождитесь статуса `healthy` у всех сервисов (`docker compose ps`).
2. `curl http://localhost:8080/readyz` вернёт `{"ok":true}`.
3. Откройте http://localhost:8080, напишите «строительная краска» и нажмите «Найти поставщиков».
4. Проверьте фильтры, карточку, сравнение, сохранение и «Запрос КП». Тёмная тема включается кнопкой с луной.

**Автотесты** (158 модульных, 9 E2E на PostgreSQL и Redis):

```bash
docker compose run --rm tools sh -c "cd server && npm ci && npm test"
docker compose run --rm -e E2E=1 tools sh -c "cd server && npm run test:e2e"
```

## Примеры ожидаемого поведения

| Действие | Результат |
|---|---|
| Боту: «Нужна фанера ФСФ 18 мм в Татарстане, только производитель» | бот распознаёт товар, характеристики (толщина 18 мм, марка ФСФ), регион и тип поставщика |
| Поиск «арматура А500С 12 мм в Татарстане» на реальных данных | заголовок «5 лучших из N», все пять компаний из Татарстана, строка «Проверено: реестр МСП · ФНС · ЕГРЮЛ · Росаккредитация» |
| «Фасадная краска» с фильтром «Только производитель» | у компаний тип «Производитель» с основанием: номер сертификата или декларации, где изготовитель — сама компания |
| Сложный запрос, который правила не разобрали | GigaChat разбирает запрос; если он недоступен, поиск идёт по правилам |
| Запрос вне справочника, например «вывы» | экран «Не нашли такой товар» с выбором категории |
| Фильтры дают 0 результатов | кнопки «Искать по всей России», «Без обязательных документов», «Убрать фильтр «только производитель»» |
| Источник недоступен (`SIMULATE_SOURCE_FAILURES`) | выдача есть и предупреждение «Часть сведений сейчас недоступна» |
| Ссылка из бота старше 15 минут | сообщение «Ссылка на подборку устарела» и форма поиска |
| «Запросить КП» у компании | готовый текст запроса, отправка в чат MAX или копирование, ссылки для поиска сайта и телефона по ИНН |
| Через двое суток после КП | бот спрашивает «Поставщики ответили?»; при «нет» присылает подборку заново |
| `GET /healthz`, `GET /readyz` | `{"ok":true}` |

## Известные ограничения

- Не подключены ГИСП, реестр недобросовестных поставщиков (ЕИС), ЕФРСБ и ГИР БО: у бесплатных источников нет
  API или доступ выдаётся по заявке, токену или договору. Интерфейс пишет об этом прямо, и фильтр «ПП РФ №719» скрыт.
- Декларации Росаккредитации загружены за ноябрь–декабрь 2024, сертификаты — по август 2026. Свежие декларации
  скачиваются только с российского IP.
- Сведения ЕГРЮЛ берутся через DaData по ключу и только для лучших кандидатов выдачи (бесплатный лимит 10 000
  запросов в сутки).
- Цена, наличие и сроки поставки не подтверждаются ни одним источником.
- Тип поставщика у большинства реестровых компаний «не определён»: по одному ОКВЭД производство не доказать.
- Реестр МСП обновляется 10-го числа каждого месяца, данные ФНС загружаются вручную командой импорта.
- Оценка кандидатов GigaChat занимает около 10 секунд, поэтому она подключается только к запросам, которые
  правила разобрали не уверенно.
- Мини-приложение в MAX открывается только по HTTPS.
- Для проверки без MAX на стенде оставлен вход из браузера (`ALLOW_BROWSER_DEMO=true`). В строгом режиме
  поставьте `false`.

## Остановка и повторный запуск

```bash
docker compose stop            # остановить, данные сохраняются
docker compose start           # запустить снова
docker compose up -d --build   # пересобрать после изменений в коде
docker compose logs -f app     # логи приложения
docker compose down            # удалить контейнеры, данные в томах сохраняются
docker compose down -v         # удалить контейнеры и данные
```

Резервная копия базы: `docker compose run --rm backup` (файл появится в `./backups`).
Восстановление:

```bash
docker compose cp backups/<файл>.dump postgres:/tmp/db.dump
docker compose exec postgres pg_restore -U supplier -d supplier --clean --if-exists --no-owner /tmp/db.dump
```

## Развёртывание на сервере

Проверено на Ubuntu 22.04: 2 ГБ ОЗУ и 2 ГБ swap, 10 ГБ диска.

```bash
apt-get update && apt-get install -y docker.io docker-compose-v2 git
git clone https://github.com/kolomyts192/mini-app-max-supplier.git && cd mini-app-max-supplier
cp .env.example .env
```

В `.env` задайте `MAX_BOT_TOKEN`, `MAX_UPDATES_MODE=polling`, `DOMAINS` (адреса через запятую),
`POSTGRES_PASSWORD` (длинный случайный пароль), `ALLOW_BROWSER_DEMO=false`, при необходимости `DADATA_API_KEY` и
`GIGACHAT_AUTH_KEY`. Затем:

```bash
docker compose -f docker-compose.prod.yml up -d --build
```

Caddy получает сертификаты Let's Encrypt для адресов из `DOMAINS`. Для этого домены должны указывать на IP сервера,
а порты 80 и 443 быть открытыми. Затем укажите HTTPS-адрес мини-приложения в настройках бота на платформе MAX.
Для webhook задайте `MAX_UPDATES_MODE=webhook`, `PUBLIC_BASE_URL`, `MAX_WEBHOOK_SECRET` и выполните
`cd server && npm run max:webhook:set`.

Обновление: загрузить новый код и выполнить `docker compose -f docker-compose.prod.yml up -d --build app`,
миграции применяются при старте. Данные загружаются теми же командами импорта, но через
`docker compose -f docker-compose.prod.yml run --rm app node dist/opendata/cli.js ...`.

Эксплуатация: `GET /healthz` и `GET /readyz` — живость и готовность; `GET /metrics` и `GET /admin/metrics?days=30` —
метрики Prometheus и успешность поиска (заголовок `X-Admin-Token`); `GET /api/sources/health` — состояние источников.

## Что изменилось после онлайн-этапа

- **Выдача.** При равном балле выше компании с подтверждённым товаром, выручкой, сотрудниками и более давней
  регистрацией, а не первые по алфавиту. Одноимённые компании («1-ЛКЗ РУ» и «1ЛКЗ РУ») занимают одно место. Компания,
  которую сертификат или декларация называет изготовителем, считается производителем.
- **Источники.** Проверка источников больше не пишет «UP» для неподключённых реестров. Подключены ЕГРЮЛ (DaData) и
  документы Росаккредитации.
- **Поиск.** Простые запросы разбирают правила, GigaChat подключается, когда правила не узнали товар.
- **Бот.** «Отобрал 5 из N» и три лучших в чате, кнопка «Пример запроса», строка источников с датами в
  приветствии, Татарстан первым в списке регионов, запрос КП и опрос «Поставщики ответили?».
- **Мини-приложение.** Заголовок «5 лучших из N», строка «Проверено: …» вместо россыпи «не подключён», скрытые фильтры
  по неподключённым реестрам, более короткая карточка, исправленная тёмная тема.
